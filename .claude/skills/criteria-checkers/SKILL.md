# Criterion Checkers (Stream 2)

A checker is the only admissible source of any number about any candidate. If you are
about to type a value about s7/s10/S22/t103 that no checker computed — stop and write
the checker.

## Checker contract (K3_CRITERIA.md §3, operational form)

1. **Exact arithmetic.** `sympy.Rational` / `fractions.Fraction` / integer arithmetic
   end-to-end. A `float` appearing anywhere in a criterion computation is a bug unless
   the checker states and propagates an explicit error bound.
2. **No network. No LLM calls. No values from model memory.** Inputs are exactly:
   (a) the candidate register in `K3_CRITERIA.md`, (b) data files in `refs/` — each
   listed in `refs/MANIFEST.md` with SHA256 and source citation. To add a literature
   value: add the file + manifest entry first, then read it from the checker.
3. **Deterministic.** Seeded where randomness is unavoidable; identical inputs ⇒
   bit-identical certificate. CI re-runs and diffs.
4. **Certificate output.** Every run writes `certificates/<criterion>_<candidate>.json`:

```json
{
  "criterion": "C1", "candidate": "K-s7",
  "verdict": "PASS", "order_checked": 200,
  "evidence": {"first_nonintegral_index": null},
  "inputs": {"refs": {"cooper_s7.json": "<sha256>"}},
  "checker_version": "<git-describe>", "timestamp_utc": "..."
}
```
   Finite-order verdicts MUST carry `order_checked`; reports render them `PASS(N)`.
5. **Golden tests before first real run.** Each checker ships `tests/test_<checker>.py`
   with one known-good control and one known-bad control (a deliberately corrupted
   input that must FAIL). A checker that has never failed on purpose is untested.

## Workflow for a new/changed checker

1. Read the criterion's definition in `K3_CRITERIA.md` — implement THAT, not your
   recollection of the mathematics. If the definition has an unresolved `TBD-AT-FREEZE`,
   stop: implementation is blocked until the freeze resolves it (escalate, don't guess).
2. Write the golden tests first; then the checker; `pytest` green.
3. Run on candidates; commit certificates.
4. Regenerate the status table: `python scripts/render_status_table.py` — this merges
   certificates + Stream 1's `open_goals.json` (for C3 flags). NEVER edit the table by
   hand; the hook blocks it and a hand edit is an integrity incident per K3_CRITERIA §5.

## Failure semantics

- A candidate failing a hard criterion (C1, C2, C3-symbolic) triggers falsification
  branch F1: append the removal entry to `K3_SELECTION_REPORT.md` in the same PR as the
  failing certificate. Do not soften, retry with different normalizations, or defer.
- If a checker result contradicts a literature value in `refs/`, do not "fix" either
  silently: open an F6-track issue with both artifacts attached.

## Definition of done

- pytest green (including the known-bad control failing as designed).
- Certificates committed; status table regenerated by script; report tables
  auto-generated (no hand-entered numbers anywhere in the diff).
- Provenance footer (epistemic-guardrails skill).
