# Cross-Consistency Verification Gate (Rule 8)

Use this skill before any release tag, after major parameter fits, or when integrating data from different modules.

## Rule 8: The Atomic Consistency Standard

> **Every numerical value (λ, w₀, w_a, H₀, m_a, α_eff, etc.) MUST be identical across:**
> 1. Python code (`simulations/`, `empirical_crucible/`)
> 2. LaTeX manuscripts (`manuscripts_and_proofs/`)
> 3. JSON benchmarks/configs (`data/theory_inputs/`, `k3_gitn_results.json`)
> 4. Lean formal proofs (where applicable)
> 5. CLAUDE.md / README documentation

**Discrepancies are release-blocking.**

## Rationale

A silent mismatch like:
- Paper says λ = 1.6724 but code uses λ = 1.67
- Lean proof assumes w₀ = −0.5485 but empirical notebook uses −0.548
- JSON config has H₀ = 71.9 but LaTeX source has 72.0

...creates hidden bugs:
- Reproduction fails
- Reviewer can't verify the chain
- Numerical claims become unfalsifiable (which value did you use?)

## Automated Consistency Checking

**Script: `scripts/cross_consistency_check.sh`**

```bash
#!/bin/bash
# Cross-Consistency Audit (Rule 8)
# Extracts all numerical constants and verifies they match across files

set -e

echo "=== Cross-Consistency Audit (Rule 8) ==="

# Extract lambda_fit from all sources
echo -e "\n[CHECK] λ parameter (lambda_fit)"

# From Python code
python_lambda=$(grep -E "lambda_fit\s*=" simulations/cosmology_solver.py empirical_crucible/*.ipynb | \
                  grep -oE "[0-9.]+\s*$" | head -1)
echo "  Python: $python_lambda"

# From LaTeX
latex_lambda=$(grep -E "\\lambda.*=.*1\.67" manuscripts_and_proofs/Part_II_Vafa_DarkEnergy.tex | \
                grep -oE "1\.67[0-9]*" | head -1)
echo "  LaTeX:  $latex_lambda"

# From JSON
json_lambda=$(jq '.cosmology.lambda_fit' data/theory_inputs/k3_gitn_results.json)
echo "  JSON:   $json_lambda"

# Check consistency
if [ "$python_lambda" = "$latex_lambda" ] && [ "$latex_lambda" = "$json_lambda" ]; then
    echo "  ✓ CONSISTENT: $python_lambda"
else
    echo "  ✗ MISMATCH DETECTED"
    echo "    Python: $python_lambda"
    echo "    LaTeX:  $latex_lambda"
    echo "    JSON:   $json_lambda"
    exit 1
fi

# Similar checks for w0, w_a, H0, mass_ratio, etc.
# [... repeat pattern for each parameter ...]

echo -e "\n✓ All parameters consistent"
```

  ```bash
    grep -v "\\(doi\\|arXiv\\|equation\|figure\\)" | head -20
  ```

  Manually verify each is in ledger


- [ ] Tag: `git tag -a v[version] -m "Release v[version] — all parameters consistent per PARAMETER_LEDGER.yaml"`

## Common Pitfalls

### ❌ Rounding mismatches
```python
# WRONG: Code uses full precision internally, but rounds for printing
lambda_fit = 1.672438492...  # full
print(f"λ = {lambda_fit:.4f}")  # prints 1.6724

# But paper says:
# "\lambda = 1.67"  # Only 2 sig figs!
```

✅ **Fix:** Be explicit about precision everywhere
```python
lambda_fit = 1.6724  # 4 sig figs, matching manuscripts
# In manuscript: "\lambda = 1.6724 \pm 0.0521"
```

### ❌ Parameter renamed but value not updated
```python
# OLD CODE: lambda_fit = 1.6724
# NEW CODE: lam = 1.67  # Oops! Typo, or genuine update?
# MANUSCRIPT: still says λ = 1.6724

# Result: Silent mismatch. Reviewer runs code, gets different χ² than paper reported.
```

✅ **Fix:** When renaming, update everywhere and write commit message explaining change:
```bash
git commit -am "refactor: rename lambda_fit to lambda_best_fit (no logic change)"
# Then verify: git diff HEAD~1 | grep lambda_fit  # Should show only name, not value
```

### ❌ Parameter fitted but uncertainty not propagated
```python
lambda_fit = 1.6724  # OK
lambda_fit_err = 0.0521  # Computed but not used

# Manuscript:
# "\lambda = 1.6724"  # ✗ Missing error bar
```

✅ **Fix:** Always report with uncertainty
```latex
\lambda = 1.6724 \pm 0.0521  % [FITTED] from DESI 2024 BAO
```
